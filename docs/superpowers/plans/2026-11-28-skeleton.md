# Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merging to `homelab` migrates the database and serves a one-page app at `https://aerc.mgryn.cc`.

**Architecture:** One image holds the FastAPI app, the built web page and the migrations. ArgoCD runs the migrate command as a `Sync` hook Job after Postgres and before the app. A release is a version tag here, then an image bump in `homelab`.

**Tech Stack:** Python 3.12, FastAPI, pydantic-settings, SQLAlchemy with psycopg 3, Alembic, pytest; Vite, React, TypeScript, `openapi-typescript`; Docker; ArgoCD, Kustomize.

**Spec:** `docs/superpowers/specs/2026-11-28-skeleton-design.md`

## Global Constraints

- Branches: `feat/skeleton` here, `feat/directive-copilot-skeleton` in `homelab`. Never merge, never push to `main`, never push a tag, never touch a live cluster. Steps marked **owner** are the owner's.
- Never run a migration against the live database. Integration runs use a local `pgvector/pgvector:pg16` container.
- No secret in either public repo.
- All configuration is environment variables. `DATABASE_URL` is the only required one, form `postgresql+psycopg://copilot:<password>@<host>:5432/copilot`.
- Importing `copilot.api` reads no environment variable and opens no connection (`make api-types` imports it).
- Footer text, exactly: `Demo only; not legal or regulatory advice. Always consult the current directive on aer.ca.`
- Image: port 8000, numeric non-root user, name `ghcr.io/maxim-grin/directive-copilot`, version `0.1.0` (matches `pyproject.toml`).
- Migrations in `copilot/migrations/versions/`, one head, immutable once committed, and compatible with the previous release's code.
- No health check calls a model or the gateway.
- Only `copilot/api.py`, `copilot/routes/` and `services/` import FastAPI. Type hints and docstrings on every function. No `print`.
- Dependencies are added with `uv add` / `npm install`, so lock files record versions.

## Review Focus

1. Database accepts the connection slowly or not at all: `/readyz` answers 503 within a few seconds, never hangs.
2. `DATABASE_URL` missing: app imports and `/healthz` works; `/readyz` is 503; migrate exits non-zero naming the variable.
3. Static fallback given `..` or an encoded slash: never serves a file outside `web/dist`.
4. `web/dist` absent (API-only development): app starts, API routes work, `/` is 404.
5. Hook runs again on self-heal, and after a rollback: second run is a no-op, ahead database exits 0, any other failure exits non-zero.

### Task 2: Migrations and the migrate command

**Files:**
- Create: `alembic.ini`, `copilot/migrations/{env.py,script.py.mako,versions/0001_enable_pgvector.py}`, `copilot/migrate.py`, `tests/test_migrate.py`, `tests/test_migrate_integration.py`

**Interfaces:**
- Consumes: `get_settings()`, `get_engine()`.
- Produces: `copilot.migrate.migrate(database_url: str) -> Literal["upgraded", "ahead"]`; `main() -> int`; `python -m copilot.migrate`.
- Revision `0001`: `upgrade` runs `CREATE EXTENSION IF NOT EXISTS vector`, `downgrade` drops it if it exists.
- `migrate` builds its Alembic `Config` in code from the package path, so it works without `alembic.ini` in the working directory. `alembic.ini` (`script_location = copilot/migrations`) serves the `alembic` CLI; `env.py` takes the URL from the config if set, else `DATABASE_URL`.
- "Ahead" test, verified on Alembic 1.20.1: `MigrationContext.get_current_heads()` minus the revisions from `ScriptDirectory.walk_revisions()` is non-empty. Plain `upgrade` there raises `CommandError: Can't locate revision identified by ...`.
